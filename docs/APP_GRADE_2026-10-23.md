## 1. What was installed, and one honest deviation

```
npx ecc-universal@2.2.3 setup        # ← what you asked for
```

That command **cannot run headless**. It exits with:

```json
{ "error": { "code": "CLAUDE_NOT_FOUND",
  "message": "Claude Code is not installed or `claude` is not on PATH. Install Claude Code, then rerun ECC setup." } }
```

`setup` is a wrapper that writes a *Claude plugin* into a Claude Code installation. There is no Claude Code runtime in this sandbox, so I used the same package's underlying installer at the same project scope:

```bash
npx --yes ecc-universal@2.2.3 install \
  --target claude-project --profile developer --no-hooks
```

On your Windows machine, `npx ecc-universal@2.2.3 setup` will work once Claude Code is installed, and will produce the same content plus plugin registration.

| Rules, commands, scripts | copied under `.claude/rules/`, `.claude/commands/`, `.claude/scripts/` |
| Install manifest | `.claude/ecc/install-state.json` |

**Hooks were declined (`--no-hooks`).** Without that flag ECC writes a hook runtime into `.claude/settings.json` that executes shell commands on tool calls in Claude Code. You told me not to break anything, so the only settings change is one line, `"includeCoAuthoredBy": false`. Re-add hooks deliberately later with `ecc install --target claude-project --profile developer --enable-hooks` if you want them.

## 4. `production-audit` score and the cap check

**78 / 100 — Launchable with caveats.**

The skill's five automatic caps, checked one by one:

| Cap | Applies? | Why |
| --- | --- | --- |
| Auth/authz missing on sensitive data | **No** | Every tenant route resolves the user from a verified JWT; `test_public_surface.py` pins what is public |
| Payment webhooks not idempotent | **No** | `payments.py:19-20` — idempotent on `reference`; a second webhook or a verify-after-webhook finds the row `success` and does nothing |
| Migrations cannot be run safely | **No, but close** | All 28 have `downgrade()`; forward chain tested on SQLite. The Postgres run is untested (B3) |
| Secrets exposed | **No** | Scanned tracked files: only `.env.example` placeholders, and `.gitleaks.toml` allows them explicitly |
| No rollback path | **No** | Alembic downgrades, encrypted backups with restore refusal checks, tag-based desktop releases |

So no cap fires. The 22 points off are quality and completeness, not disqualification.

For the **chain edition**, the same rubric scores 61 because §5's B1/B2 are not defects but *absent features*. A grade cannot exceed what exists.

## 6. What is genuinely strong — do not "fix" these

- **The money model.** Integer kobo, `Decimal` at the boundary, one rounding per line, one tax computation per document. Every one of those is a decision most teams get wrong, and `test_money.py` proves it at 99% coverage.
- **The test-to-code ratio.** 501 backend tests against 31k lines, 84% coverage, a contract test that fails when the frontend and backend disagree about a field.
- **Tenant isolation in application code** is consistent: `business_id` filtering plus a 404-not-403 policy on cross-tenant reads, which leaks less than the alternative.
- **The offline design** is the rare version that handles conflicts honestly — the queue goes to a `conflict` state with an email/SKU owner explanation instead of silently overwriting.
- **Zero bare `except:`** in the backend, zero `console.log` in the frontend, four TODO comments in 66k lines.
- **Documentation depth.** 30 documents including a security audit, a launch checklist, and a run guide that was verified end-to-end yesterday.

## 11. What changed after the grade (same day, later commits)

The grade above is the snapshot it claims to be. This section records what
was then fixed, so nobody re-fixes it. Scores are **not** re-scored here; only
findings are closed.

**Frontend (A1–A12, A14):** `<html lang>`; the hamburger no longer carries an
inline `display` (CSS owns visibility, so the phone nav exists); the mobile
drawer uses `visibility` instead of `aria-hidden` plus `Escape` and focus
handling; semantic text tokens (`successText`/`warningText`/`infoText`,
`onSurfaceMuted`) replace 4.29:1 `outline` and 1.9:1 tints; `PageHeader`
stacks its title and subtitle; the skip link, focusable `<main>` and
route-change focus reset are in `AppShell`; `ForecastCard` uses `warningText`;
the order pickers have accessible names; 128 fractional font sizes snapped;
`CoopTable` scrolls instead of squeezing; eight raw `e.message` toasts became
`describeError()` sentences; display copy is `Co-op` everywhere; and a test
now ties every type token's line-height to its size (32 frontend tests).

**Build (new, found while verifying the above):** a production build without
`VITE_CLERK_PUBLISHABLE_KEY` used to *succeed* and ship a blank screen — Vite
inlined the missing value, `main.tsx`'s guard folded to a top-level throw, and
the bundler tree-shook every screen away (a 51 kB entry chunk containing no
app). The build now fails with an explanation instead. CI passes a throwaway
placeholder key because the value is a build-time input and that bundle is
never deployed.

**Website (W1–W15):** placeholders, build instructions in customer-facing
copy and `#top` CTAs are gone; the tour renders only when real screenshots
exist; contact and signup URLs are single constants that render only when
filled; icons are SVG; the phone nav exists; `prefers-reduced-motion`,
`<html lang>`, a persistent theme toggle, live plan data, the Naira/USD
distinction and the trial wording were all corrected. Canonical, `og:url` and
`og:image` are deliberately absent — they need the production domain, and an
invented domain is worse than a bare preview.

**Still open, unchanged by the above:** A15 (1,308 inline style objects, the
1,000-line order pages), the 852 kB `ui` and 936 kB `chart` chunks, no
component/E2E test layer, and every P0 in §7 (SQLCipher, Postgres RLS proof,
live Paystack charge, code signing). Nothing here moves the chain-edition
score.
