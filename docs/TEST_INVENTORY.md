## Features in the checklist that don't exist (so have no tests, correctly)

- **Refunds** — no `refunded` order status; cancellation is the reversal path (tested).
- **Discounts** — no discount field on orders/line items.
- **`past_due` / `inactive` subscription states** — the machine is free/trial/paid only.

Don't write tests for these; they'd be testing phantoms.

## The three questions, answered directly

**1. Genuinely untested that could break on Sunday?**
Only three, and all are *manual staging checks*, not missing unit tests:
- **Clerk auth on the production instance** — mocked in every test; dev-vs-prod is the #1 silent blocker. Walk signup→login on staging.
- **The live Paystack charge** — `test_paystack_live.py` skips without egress; do one real minimum charge.
- **Desktop install → update** — `electron-updater` only runs packaged; verify on a clean Windows machine.
Plus one code gap that's *visible* on launch day: **timezone-day aggregation** in the revenue graph (P1) — a sale near midnight could land on the wrong day.

**2. Untested but safe to defer past launch?**
Network-timeout and oversized-payload at the HTTP edge; backend disk-full; AI-forecast edge cases; some report filter combinations; systematic cross-tenant UPDATE/DELETE per table (read isolation is already covered). All P1/P2 — none block a pilot.

**3. Tested but weak (asserts little / always skips / passes for the wrong reason)?**
- **`test_rls.py` functional test** — Postgres-gated, so in a normal SQLite CI run it **skips**; the always-on part only checks the DDL *string*, not real isolation. (It does run — and pass — when `TEST_DATABASE_URL` is set, e.g. against staging.)
- **`test_paystack_live.py`** — **always skips** without egress; green in CI but proves nothing there.
- **`setPermissionRequestHandler`** — not weak, **absent**: a hardening control with no test at all.

## The only P0 list (Friday)

There are no P0 *unit tests* to write. The P0 work is the 10-step manual smoke on a
staging build (fresh install → signup → product → sale → graph → export → restore
→ Paystack live charge → re-login persists paid → second account can't see the
first). If those 10 pass, ship. The P1 code gaps (timezone aggregation, the
permission-handler test, cross-tenant write/delete) are Wednesday work.
